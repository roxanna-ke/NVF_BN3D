# BN3D building1 NVF reproduction

This adapter follows `NVF_BN3D_v1.md`. It uses the raw `House.obj` and
`data/REAL/building1/meta_data.json`; `bn3d_processed` is not an input.
All image observations and held-out GT are rendered by one `BN3DScene`.

## Local preparation

From this repository root:

```bash
python tools/bn3d_nvf.py prepare --config configs/bn3d_nvf.json
```

This checks the 200 camera records and image paths and writes a manifest with
input hashes and paired initial-view IDs. It does not run Blender or train NVF.
The original images are not used in training or evaluation.

## Run:ai container

Copy the repository and the raw OBJ directory (including MTL and texture files)
and `data/REAL/building1` to persistent storage. In a copy of the JSON config,
replace `mesh_path`, `data_root`, and `output_root` with their container paths.
Run from the NVF repository root in the CUDA/Blender environment described in
the upstream README. A writable output directory is required.

```bash
python tools/bn3d_nvf.py run --config configs/bn3d_nvf.json --policy nvf --seed 42
python tools/bn3d_nvf.py run --config configs/bn3d_nvf.json --policy random --seed 42
```

Repeat both commands for seeds 43 and 44. `nvf` and `random` use the same NVF
field and training stages; the chosen candidate differs. Each run trains from
3 through 20 observations, with a final training and evaluation on all 20.
Runs write separate checkpoints, observations, trajectories and per-observation
metric JSON files. The run fails if a `complete.json` already exists.

After all six runs finish:

```bash
python tools/bn3d_nvf.py summarize --config configs/bn3d_nvf.json
```

The summary writes per-observation metrics and paired final differences to
`output_root/summary`. An interrupted run retains its outputs and has no
automatic resume; move it aside before rerunning that policy and seed.

## Data and coordinate assumptions

The Blender OBJ import follows `AVS/tools/bn3d_common.py`: OBJ forward axis
`-Z`, up axis `Y`, all imported meshes retained. The imported mesh bounding-box
center is moved to zero and its longest side scaled to two. The same world
transform is applied to every `camtoworld` translation. This alignment must be
verified in the container by rendering known metadata cameras and comparing
silhouettes to the archived images before relying on experiment metrics.

The experiment uses metadata indices `0,5,...,195` as 40 held-out cameras and
draws three initial cameras from the other 160 for each seed. RGB, depth and
visibility labels used for NVF are generated by the original NVF pipeline;
the stored BN3D depth/normal/semantic images are not training inputs.

Current code has only passed local static checks. Blender rendering, CUDA
training, visibility projection, quantitative results and checkpoint resume
have not been validated here.
