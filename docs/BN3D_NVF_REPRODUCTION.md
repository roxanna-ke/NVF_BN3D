# BN3D building1 NVF reproduction

This adapter uses raw `House.obj` and `data/REAL/building1/meta_data.json`.
All observations and held-out GT are rendered by `BN3DScene`. The active
experiment is seed 42, with NVF and Random submitted separately.

## Submit from a Run:ai login node

The repository must be visible inside the job at
`/mnt/scratch/imos-students/ke/repos/NVF_BN3D`. From this repository, run:

```bash
bash bn3d_nvf.sh
bash bn3d_random.sh
```

Each script submits one seed 42 GPU job using the existing scratch and home
PVCs. Defaults are image `registry.rcp.epfl.ch/imos-ke/avs:v0.0.1` and Python
`/mnt/home/conda-envs/pun/bin/python`. Override with `MY_IMAGE` and
`PYTHON_BIN`; Run:ai project, GPU, node pool and PVC names also have the same
environment overrides as the existing BN3D scripts.

## Inside each job

The worker verifies CUDA and imports, prepares input hashes, and renders
metadata camera 0 with one CPU Blender sample. The silhouette must reach IoU
0.9 against the archived semantic mask. Inspect
`output_root/prepared/preflight_{nvf,random}.png` for appearance and lighting.
A local preflight reached silhouette IoU about 0.993.

```bash
python tools/bn3d_nvf.py run --config configs/bn3d_nvf.json --policy nvf --seed 42
python tools/bn3d_nvf.py run --config configs/bn3d_nvf.json --policy random --seed 42
```

These commands are run by the two scripts. `nvf` and `random` use the same NVF
field, training stages and candidate sampler; only candidate selection differs.
Each run trains at observation counts 3 through 20 inclusive: 18 separate
5,000-step NeRF trainings and 17 new views. Each also trains visibility and
variance, evaluates 40 held-out views, and computes geometry metrics. Runs
write checkpoints, observations, trajectories, metrics and `timing.json` with
an updated remaining-time estimate. A completed run is skipped. An incomplete
run is retained and must be moved aside before resubmission.

The later job summarizes automatically after both runs finish:

```bash
python tools/bn3d_nvf.py summarize --config configs/bn3d_nvf.json
```

The summary writes per-observation metrics and paired final differences to
`output_root/summary`. With one seed, standard deviation is reported as zero.

## Data and coordinate assumptions

The Blender OBJ import follows `myRepo/tools/bn3d_common.py`: OBJ forward axis
`-Z`, up axis `Y`, all imported meshes retained. The imported mesh bounding-box
center is moved to zero and its longest side scaled to two. The same world
transform is applied to every `camtoworld` translation. The BN3D mesh already
fits inside the clipping box, so extraction bypasses NVF's boolean clip.

The experiment uses metadata indices `0,5,...,195` as 40 held-out cameras and
draws three initial cameras from the other 160 for seed 42. RGB, depth and
visibility labels used for NVF are generated by the original NVF pipeline;
the stored BN3D depth/normal/semantic images are not training inputs.

The PUN Conda environment has Python 3.10, Torch 2.0.1 CUDA 11.8, Blender 3.6,
and the required imports. Its `nerfacc` is a local PUN build rather than the
upstream NVF README's Git revision. CPU preflight and light tests pass; full
CUDA training and final quantitative results have not been validated locally.
